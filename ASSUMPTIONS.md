# Принятые допущения

Документ фиксирует решения, которые PLAN.md не задаёт однозначно. Если допущение
перестаёт быть верным, его нужно изменить вместе с кодом и тестами.

## Данные и расписание

1. **Идентификаторы учеников.** Используются стабильные `s01`…`s33` в порядке
   списка из §2.1 плана. Номер строки на фотографии журнала никогда не является ID.
2. **Подгруппы английского.** 2к207 — ученики `s01`…`s17`, 2к202 — `s18`…`s33`.
   Остальные предметы относятся ко всей группе.
3. **Преподаватели английского.** В PLAN.md не указаны фамилии преподавателей
   подгрупп. Поля оставлены пустыми; кабинеты — `2к207` и `2к202`. Это не
   выдуманные данные, а честный пропуск. Уточняется в `schedule.json`.
4. **Начало учебного периода.** `weekAnchor = 2026-08-31` — понедельник недели,
   в которую попадает 1 сентября 2026 года; `firstWeekType = numerator`. Якорь
   выровнен по понедельнику, иначе чётность переключалась бы посреди недели.
   Обе настройки лежат в `data/schedule.json` и меняются без правки JavaScript.
5. **Период действия расписания.** Уроки имеют `validFrom = 2026-09-01` и не
   имеют `validTo`: дата окончания семестра в плане не указана. Правила замен
   также действуют с этой даты.
6. **Служебные события.** «Разговоры о важном» и «Россия — мои горизонты»
   помечены `service: true` и не участвуют в расчёте домашних заданий и оценок.
7. **Замены по чётности.** Специальные правила знаменателя хранятся в
   `schedule.json.replacementRules`, а не в JavaScript. Индивидуальная замена из
   PDF имеет приоритет над правилом для той же пары.
8. **Пустые данные.** Оценки, задания, замены и спорные записи на старте пусты.
   Никакие оценки, даты и замены не придумываются. Счётчики дежурств всех
   33 учеников инициализированы нулём.

## Ревизии и публикация

9. **Единая revision.** Все семь файлов данных и `manifest.json` публикуются с
   одной строкой `revision`. `manifest.json` записывается последним. Пока набор
   файлов несогласован, сайт показывает состояние ошибки, а не старые данные.
10. **CAS-конфликт.** GitHub Contents API не транзакционен. При `409`/`422`
    операция перечитывает все файлы, заново применяет идемпотентные изменения и
    повторяет публикацию не более 5 раз с экспоненциальной паузой.
11. **Идемпотентность.** Telegram `update_id` хранится в локальном состоянии
    после успешной обработки. Данные дополнительно идемпотентны по естественным
    ключам: `taskId`, `duty date + reportId`, `gradeId`, `replacementId`.
12. **Локальное состояние.** `bot_state.local.json` содержит только служебные
    отметки, квоты и ID обработанных обновлений. Он не публикуется и исключён из Git.

## Бот и время

13. **Часовой пояс.** Все расчёты — `Europe/Moscow`. «24:00» реализуется как
    закрытие предыдущего дня в 00:00 следующей календарной даты.
14. **Дежурства.** Выбор создаётся в 00:00 для текущего буднего дня. Суббота и
    воскресенье пропускаются; суббота возможна только отдельным ручным
    исключением, которого на старте нет. Начисляются только имена из последнего
    однозначного отчёта «Дежурили …». Без отчёта день закрывается без начисления.
15. **Кто может писать.** Только ID из `ALLOWED_TELEGRAM_IDS`. Проверка идёт до
    скачивания файлов и до вызовов внешних API. Username не используется.
16. **Домашние задания.** Одна запись на пару «предмет + дата выдачи». Повторное
    сообщение с тем же предметом и датой обновляет текст, а не создаёт дубль.
    Ближайший урок ищется строго после даты выдачи с учётом чётности недели и
    отмен замен. Горизонт поиска — 370 дней; если урок не найден, запись не
    создаётся и пользователь получает понятную ошибку.
17. **Формат даты ДЗ.** `ДД.ММ`, `ДД.ММ.ГГ`, `ДД.ММ.ГГГГ`, `ДД/ММ`; без даты
    используется дата сообщения. Год из двух цифр трактуется как 20xx.

## Gemini

18. **Модели и квоты.** Список моделей и лимиты (5 RPM, 20 RPD, 250k TPM)
    задаются окружением и являются локальной страховкой, а не гарантией Google.
    При исчерпании лимита обработка останавливается без потери уже сохранённых
    оценок.
19. **Поворот фотографии.** Сначала применяется EXIF orientation и сжатие.
    Дополнительные повороты 90/180/270 отправляются только как ограниченный
    fallback при пустом или низкоуверенном результате; все четыре варианта
    сразу не отправляются.
20. **Неразборчивые значения.** Точка, пустая клетка и маркер `А` не являются
    оценкой. Сырое значение `Н`/`H` рядом с `4` не превращается в `4`
    автоматически: запись получает низкую уверенность и требует проверки.
21. **Неполный журнал.** Отсутствие клетки в ответе Gemini никогда не удаляет и
    не перезаписывает сохранённую оценку.
22. **Версии распознавания.** В каждой оценке сохраняются модель,
    `promptVersion` и `recognitionSchemaVersion`.

## VK и PDF

23. **Доступ к VK.** Для автоматического поиска нужны `VK_GROUP_ID` и
    `VK_ACCESS_TOKEN` (сервисный токен). Без них бот не падает: сообщает, что
    автоматический импорт недоступен, и принимает PDF, пересланный разрешённым
    пользователем. Selenium и браузерная автоматизация не используются.
24. **Разбор PDF.** PDF сначала читается как текст через `pypdf`; вложенный код
    не исполняется. Парсер рассчитан на построчный текст и фильтр `108М`.
    Реальная вёрстка PDF КГАМТ может потребовать уточнения шаблона; это
    ограничение отмечено в README. Если строк 108М нет — замены не создаются.
25. **Безопасность ссылок.** Скачиваются только HTTPS-ссылки с публичным
    IP-адресом, проверенным по DNS; проверяются размер, MIME и сигнатура `%PDF`.

## Фронтенд и приватность

26. **GitHub Pages публичен.** Любой, кто знает URL, увидит ФИО и оценки.
    Авторизации нет, потому что статический сайт её не обеспечивает. Это
    осознанно принятое ограничение из PLAN.md.
27. **Никаких секретов в браузере.** Сайт только читает `data/*.json`; записи в
    GitHub из JavaScript нет.
28. **Экранирование.** Любой внешний текст (ФИО, ДЗ, названия предметов,
    предупреждения Gemini) проходит через `escapeHtml` перед вставкой в DOM.
29. **Кэширование.** Файлы запрашиваются с `?v=<revision>`. При несовпадении
    revision сайт перезапрашивает manifest и файлы один раз, затем показывает
    ошибку с кнопкой повтора.
30. **Резервная копия.** Состояние сайта до переработки зафиксировано тегом
    `pre-rebuild-2026-11-18` и историей ветки `main`.

## Безопасность секретов

31. **Уже опубликованные секреты.** В рабочем каталоге находились `1.py` и
    `vk_tokens.json` с токенами VK, а в черновике `automeh.py` — заполненные
    Telegram/GitHub/Gemini-переменные. Эти файлы не коммитятся. Владельцу
    необходимо отозвать и перевыпустить все такие токены; бот читает только
    переменные окружения.
32. **Логи.** В логи попадают тип операции, hash изображения, количество
    результатов и безопасно сокращённые ошибки. Токены, полные ответы API, ФИО,
    тексты ДЗ и сырые сообщения не логируются.
33. **Периоды аттестации во фронтенде.** В данных нет явных границ аттестаций.
    «Текущая аттестация» означает текущий календарный месяц, «предыдущая» —
    предыдущий календарный месяц, «все периоды» — без фильтра. Итоговая отметка
    (`entryType = attestation`) показывается отдельно и не входит в средний балл.
    Если колледж опубликует точные границы, их нужно добавить в конфиг и заменить
    этот расчёт.
34. **Проверка вёрстки.** Экраны проверены в браузере на ширинах 360, 390, 768 и
    1280 px: горизонтальной прокрутки нет, состояния загрузки/ошибки/устаревших
    данных и все пять разделов отображаются. Для визуальной проверки
    использовался временный набор данных вне репозитория; в `data/` он не
    попадает.
